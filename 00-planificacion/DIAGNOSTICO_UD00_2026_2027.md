# Diagnóstico inicial de UD00 — Curso 2026/2027

## Finalidad

UD00 no tendrá una calificación independiente. Antes de comenzar el recorrido
se pasarán tres cuestionarios diagnósticos en Moodle para conocer el punto de
partida real del grupo y decidir dónde dedicar más tiempo de explicación,
práctica y refuerzo.

Los resultados se analizarán de forma agregada. No se utilizarán para ordenar,
penalizar ni calificar al alumnado.

## Cuestionarios

| Cuestionario | Qué diagnostica | Dificultad esperada |
|---|---|---|
| Java | Sintaxis, tipos, control de flujo, clases, colecciones, excepciones y lectura de código | Baja o irregular; se espera poca experiencia directa aunque parte del grupo pueda venir de Kotlin |
| MongoDB | Documentos, colecciones, consultas, actualización, modelado y diferencia entre embeber y referenciar | Baja; se comprobará si existe experiencia previa real y no solo contacto superficial |
| SQL | `SELECT`, filtros, joins, claves, restricciones, agregaciones y diseño relacional básico | Comparativamente mayor, aunque se comprobará la comprensión y no solo la memorización de consultas |

## Diseño operativo

- Mantener tres cuestionarios independientes para que los resultados no se
  mezclen.
- Usar preguntas de opción múltiple, verdadero/falso, emparejamiento y lectura
  breve de código o consulta.
- Incluir algunas preguntas de transferencia, no solo definiciones.
- Mantener una duración aproximada de 10-15 minutos por cuestionario.
- No mostrar una nota global de UD00 ni incorporarla al calificador del módulo.
- Registrar porcentajes de acierto por bloque y por concepto, no solo la media
  total.
- Revisar los resultados antes de fijar el ritmo de las primeras sesiones.

## Decisiones didácticas derivadas

- Si Java queda claramente por debajo, ampliar la nivelación y conectar cada
  ejemplo con el backend de UD01/UD02.
- Si MongoDB queda claramente por debajo, comenzar por documentos, CRUD y
  consultas antes de exigir diseño por patrones de acceso.
- Si SQL es el bloque más sólido, dedicar menos tiempo a sintaxis elemental y
  más a restricciones, diseño, JSONB y comparación con MongoDB.
- Si el grupo es muy heterogéneo, preparar una ruta mínima común y actividades
  de ampliación, en lugar de ralentizar todo el bloque por un único resultado.

## Publicación y privacidad

Los cuestionarios se crearán e importarán directamente en Moodle. Los bancos
GIFT permanecerán privados y no se publicarán en GitHub Pages.
