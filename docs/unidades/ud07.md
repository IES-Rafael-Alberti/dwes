# UD7 — Proyecto integrador de DWES

## Propósito

UD7 es el proyecto de cierre de **Desarrollo Web en Entorno Servidor**. Demuestra que el alumnado puede construir, probar, documentar y defender un servidor propio. No es el Proyecto Final de Grado ni se sustituye por trabajo de interfaz, diseño o despliegue.

## Prerrequisito y momento de elección

La propuesta se presenta tras finalizar Spring Boot y se aprueba con el docente. Laravel puede seguir en desarrollo cuando se elige el tema; por eso el dominio debe ser viable desde el conocimiento ya impartido y ajustarse después con acompañamiento, no esperar a que el framework esté completo.

El calendario se adapta al centro, con la referencia de llegar casi a la finalización a finales de enero. Los hitos son relativos y no fijan fechas artificiales.

## Stack y fronteras

El servidor debe usar **Spring Boot 4 con Java 25** o **Laravel 12 con PHP 8.4**. PostgreSQL es la persistencia por defecto; MySQL requiere aprobación como alternativa y MongoDB solo puede aceptarse si su diseño se ha impartido al grupo y el dominio lo justifica. **Node.js, Express y cualquier framework de servidor no impartido no se aceptan como evidencia DWES.**

La coordinación con Cliente, Diseño de Interfaces Web y Despliegue de Aplicaciones Web **solo sincroniza calendario y ritmo**; no crea entregables compartidos ni un ámbito de evaluación compartido. DWES revisa independientemente el flujo de servidor: acción visible, petición, endpoint, regla/servicio, persistencia y respuesta o error. Reutilizar un cliente de otro módulo es opcional y solo aporta a DWES cuando demuestra ese flujo completo y visible mediante el servidor propio permitido del estudiante, incluidos el manejo de respuestas y errores.

## Evidencias esperadas

- Dominio no trivial: al menos tres reglas, estados, restricciones o procesos independientes y verificables, no solo CRUD plano.
- Diseño razonado y actualizado si cambia: diagrama ER, relaciones y restricciones para datos relacionales, y correspondencia con entidades/modelos y migraciones.
- Arquitectura con responsabilidades separadas y migraciones reproducibles; en Spring Boot se aplican las capas vistas y en Laravel se mantiene una separación idiomática justificable.
- Validación, errores y seguridad proporcionada al dominio; autenticación/autorización cuando aplique.
- Pruebas automatizadas, documentación y puesta en marcha local reproducible.
- OpenAPI cuando se exponga API y evidencia real de integración cliente-servidor si hay cliente.
- Repositorio Git accesible al docente, con commits, issue/tablero equivalente y etiquetas/releases periódicas; sin secretos ni `.env` versionados. CI/CD es un plus opcional, no un requisito ni un peso de calificación.
- [Declaración de IA](../plantillas/plantilla-declaracion-uso-ia.md) obligatoria: indica **No** si no se usó; si se usó, registra propósito, cambios o rechazos y evidencia de verificación (pruebas, documentación oficial o comprobación manual).
- Defensa con recorrido vivo del servidor y un cambio pequeño dirigido o razonado, incluida la explicación de las decisiones y resultados de IA usados.
